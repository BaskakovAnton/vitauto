1. Вердикт

Связка УНФ + АРМ закрывает документный каркас закупки и отгрузки и часть статусной ленты, но не закрывает сквозной happy path «как на схеме».

Типовая УНФ даёт документы и остатки. АРМ даёт рабочий стол менеджера/снабжения и смену статусов. Не закрыты: полноценный подбор номенклатуры (M2), размещение по зонам (K2), задания и контроль комплектации «как процесс», уведомления о готовности, отгрузочная ведомость, контроль оригиналов документов. Портал поставщика и клиентский вход — вне 1С.

18 шагов сценария. «Покрыто» = можно пройти учётными документами + статусами АРМ без обязательной новой разработки. «Дописать» = K2, M11, M12, M15∥K7. «Вне 1С» = клиент / поставщик / физическая выдача.

2. Легенда итога по шагу

  • покрыто — УНФ и/или АРМ достаточны для прохождения шага в рабочем режиме.
  • частично — есть документ, статус или поле, но нет полного действия схемы (ветвление, печать, зона, уведомление, отдельная роль).
  • дописать — ни УНФ, ни текущий АРМ шаг не закрывают; нужна доработка в 1С.
  • вне 1С — сознательно вне системы или внешний контур (портал, клиент, факт на складе).

3. Сводка по шагам: УНФ · АРМ · итог · остаток

№ Шаг схемы УНФ АРМ Итог Что уже есть Что останется дописать
1 N1 — Заявка Excel / фото нет част. вне 1С Менеджер заводит заказ в 1С. Клиентский канал (мессенджер/Excel) — процессный, не АРМ. OCR/портал — отдельное решение.
2 M1 — Загрузка заявки в 1С част. част. частично Заказ покупателя (УНФ) + табличный ввод в АРМ. Парсер Excel по шаблону; автосопоставление артикулов.
3 M2 — Поиск и подбор номенклатуры част. нет частично Справочник и ручной поиск номенклатуры УНФ; ручной выбор в строке АРМ. Критично: кроссы / аналоги, матчинг факта клиента, ветка «есть остаток → резерв / нет → закуп / создать карточку».
4 M4 — Заказ поставщику есть есть покрыто Документ «Заказ поставщику» + создание из АРМ. Не требуется для базового прохождения.
5 P1 — Обработка у поставщика нет нет вне 1С Ручной контакт / подтверждение вне системы. Портал / сайт поставщика — только если включать в объём отдельно (в БТ/ФТ обычно вне релиза).
6 M7 — Контроль оплаты есть есть покрыто Оплаты и взаиморасчёты УНФ + статус «Оплачено» в АРМ снабжения. При желании — жёсткая связка «нет оплаты → нельзя в путь» (сейчас статусы АРМ и оплаты УНФ не обязаны быть синхронизированы правилом).
7 P2 — «В пути» нет част. частично Статус «Товар в пути» в АРМ. При необходимости: способ доставки, ожидаемая дата, контроль «доставлено».
8 K1 — Приёмка по УПД есть част. покрыто Приходная накладная УНФ; статусы «Приходуется» / «На складе» в АРМ (роль «Снабжение»). Поля УПД в АРМ; автоперевод статуса с прихода; отдельный UI кладовщика (если нужен по ролям ТЗ).
9 K2 — Размещение по зонам нет нет дописать Склады УНФ (без зон Витавто). Дописать: зоны (приёмка / малый / большой / неопознанные и т.д.) и операция размещения.
10 M8 — Уведомление о приходе нет част. частично Статус прихода виден в списке АРМ. Явное уведомление менеджеру (или принять «смотрит список» как правило работы).
11 M9 — Задание на комплектацию нет част. частично Смена статуса на комплектацию в АРМ. Документ/команда «задание» с составом позиций под заказ.
12 K3 — Комплектация + сборочный лист нет част. частично Статусы «Комплектуется» / «Собран». ПФ сборочного листа; отметки дефекта / недостачи (в БТ печатный комплект часто вне релиза — согласовать).
13 M10 — Контроль комплектации нет част. частично Смена статусов по строкам. Явный «ок / отклонение» + розыск позиции при отклонении.
14 M11 — Уведомление о готовности нет нет дописать — Дописать: статус/признак «готово к отгрузке» и/или уведомление.
15 M12 — Отгрузочная ведомость нет нет дописать Типовые ПФ расходной накладной (не ведомость Витавто). Дописать: ПФ отгрузочной ведомости (в текущих БТ/ФТ часто вынесено из релиза 1.0 — требует явного включения в объём).
16 K5 — Отгрузка клиенту / ТК есть част. покрыто Расходная накладная УНФ; дата/номер отгрузки в АРМ. Отдельный АРМ кладовщика на отгрузку — по желанию ролевой модели.
17 N2a — Товар у клиента нет част. вне 1С Фиксация реквизитов отгрузки в АРМ. Факт выдачи — вне системы; клиентский кабинет не требуется для учёта.
18 M15 ∥ K7 — Контроль документов нет нет дописать — Галка «подписано / оригинал получен» у менеджера и склада.

Шаги со статусом «частично» (M1, M2, P2, M8–M10, K3) тоже дают объём доработок — см. приоритеты в разделе 5; в счётчике «дописать» только полностью пустые шаги схемы.

4. Что уже можно считать закрытым связкой УНФ + АРМ

  • Учётный каркас: заказ покупателя → заказ поставщику → оплата → приходная → расходная.
  • АРМ менеджера: строки, цены/кол-во, создание заказа поставщику, табличная загрузка, реквизиты отгрузки.
  • АРМ снабжения: статусы оплаты, «в пути», прихода, комплектации, сборки.
  • Связь строк АРМ с документами УНФ по заказам.

5. Остаток: что дописать (приоритет)

Приоритет Блок Зачем на happy path Комментарий по объёму
P0 M2 — подбор номенклатуры и ветвление «резерв / закуп» Без этого сценарий «остатка нет → закуп» на схеме не автоматизирован. Крупный блок; опора на НСИ УНФ, логика — в АРМ.
P1 K2 — зоны и размещение После приёмки схема требует размещение, затем уведомление о приходе. НСИ зон + операция в АРМ/складе.
P1 M9 → K3 → M10 — комплектация как процесс Сейчас только статусы; нет задания, листа, ok/отклонения. Можно поэтапно: сначала задание+контроль, ПФ — отдельно.
P2 M11 — готовность к отгрузке Мост к отгрузке и ведомости. Относительно небольшой (статус / признак / сигнал).
P2 M12 — отгрузочная ведомость Финиш менеджера перед отгрузкой на схеме. Печатная форма; часто вне релиза 1.0 — нужно явное «включить».
P2 M15 / K7 — контроль документов Закрытие сценария на схеме. Поля + права; без глубокой интеграции.
P3 M1 — Excel-парсер; жёсткая связка оплаты; UI кладовщика Удобство и дисциплина процесса, не блокер учёта. По согласованию приоритетов с заказчиком.
— P1 портал поставщика; N1 клиентский канал На схеме есть, в 1С не живут. Не «дописать АРМ»; отдельное решение или оставить ручным.

6. Как читать это заказчику одной фразой

УНФ ведёт документы и деньги/складской учёт. АРМ ведёт статусы заявки. Чтобы схема happy заработала целиком, дописать нужно прежде всего подбор номенклатуры, зоны размещения и процесс комплектации; затем готовность, ведомость и контроль документов. Портал поставщика и клиентский вход УНФ/АРМ не заменят.

7. Ограничения отчёта

  • Только сценарий «Основной: закупка → отгрузка». Резерв со склада, возвраты, виртуальный закуп, механик — не входят.
  • Оценка типовой УНФ — по стандартным возможностям редакции 1.6 без нестандартных обработок заказчика вне данного расширения.
  • Документ информационный; не заменяет акт приёмки и не фиксирует новый объём договора, пока стороны явно не согласуют остаток из раздела 5.
