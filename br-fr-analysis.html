6. Минимальный состав документа ФТ

База: сценарии из файла «БТ_…» + уточнения Михаила №2 + пакеты Максима после дедупа п.3/п.4.

Блок ФТСодержание
FR-ЗП Заказ покупателяПоля факт/учёт, загрузка файла, подбор в текущую строку, авто-строки дозаказа, проведение и запреты
FR-АРМКолонки, фильтры, группировки, смена поставщика/цены, статусы, отмена/возврат, запрос удаления
FR-ЗС + приходСвязь со строкой покупателя, резерв при приёмке, срочность
FR-НСИ / прочееТолько то, что утвердят в границах БТ (печать наименования / внутр. затраты — отдельным решением)
FR-NFRРоли/RLS, блокировка строк при одновременной работе, производительность грида
ТрассировкаКаждый FR → пункт БТ → источник (Максим / Михаил / канон) → узел process при наличии

7. Рекомендуемый порядок работ

  1. Границы v1 — только «заказ + АРМ + связка поставщик/приёмка» или полный канон process.
  2. Протокол решений по 5 конфликтам (особенно цена = РРЦ как в ТЗ).
  3. Документ БТ (бизнес-язык) → затем ФТ с трассировкой.
  4. Смета под утверждённый скоуп (не смешивать с комфорт 430–620 на весь остаток канона, если v1 уже).
  5. Опционально: матрица покрытия FR ↔ узлы process.html.

8. Детали по файлам

БТ_ВИТ_Авто_20260121.docx

Структура

  • Доработки в документе «Заказ покупателя» (поля, подбор, авто-строки, создание заказа поставщику при проведении, роли).
  • Сценарий использования заказа (пошагово: файл → сопоставление → дозаказ → проведение → запрет отмены проведения для обычного пользователя).
  • Доработки обработки «АРМ» (колонки, статусы, фильтры, группировки, отмена/возврат, удаление по запросу) + сценарий АРМ.
  • Прочее: удаление обработки сопоставления; поля номенклатуры для печати; документ/регистр/отчёт «внутренние нужды».

Почему не БТ: нет «зачем бизнесу», нет границ, нет измеримых результатов — только «что доработать в 1С».

перечень работ Максим.docx

Пакеты (сжато)

  • 1. Заказ покупателя: авто-резерв, ввод на основании → заказы поставщикам, колонки гос. номер / срочно / база, снять с резерва; приёмка с привязкой к заказу покупателя; обработка непроведённых заказов для сопоставления.
  • 2. АРМ менеджера: всё незакрытое в одной таблице; остаток / в пути / дозаказ; блокировка строк; создание расходной.
  • 3–4. Заказ покупателя V2 (почти дубль): % наценки, FIFO/партии, артикул, НДС/ед. изм., группировка в заказе поставщику, комментарий для снабжения и др.

Часы и стоимость не заполнены — для коммерции пока непригоден.

Оценка Михаил.xlsx

Лист «ТЗ №1»

  • Приёмка ↔ заказ покупателя + срочно; форма «как УКД»; артикул; форма оплаты = НДС; группировка ЗП; НДС по типу поставщика.
  • Комментарии Михаила: часть пунктов «неактуально / будет из АРМ», вопросы по смыслу УКД и единицам измерения.

Лист «ТЗ №2»

  • Скрытие полей, «Можно отгрузить», роли на заказе, партии/себестоимость/НДС в АРМ, подбор в текущую строку, автосоздание ЗП, формула остатков, статусы, фильтры, отмена/возврат, роли склад vs продажи, запрос на удаление.
  • Итого часов в файле: 0 — оценка не завершена.
Следующий шаг: живой обход с заказчиком — протокол апрувов; карта и смета — protocol-map; проекты документов — БТ / ФТ. (блокеры → границы → детали). Тексты БТ/ФТ — только после утверждённых пунктов.
